# expo-ble-kit

## 0.1.0

### Minor Changes

- c9324ab: First preview of expo-ble-kit, Bluetooth Low Energy for Expo and React Native. The central role: permissions and adapter state without surprise prompts, scanning with filters (several scans share the radio), connections with timeouts and `AbortSignal` cancellation, service discovery, reads and writes (long ones too), descriptors, notifications and indications, MTU and RSSI, typed errors (`BleError` with a `code`), UUID helpers and constants, the React hooks `useBleState`, `useBlePermissions`, `useScan`, `usePeripheral` and `useCharacteristicValue`, a config plugin for the permissions, and `expo-ble-kit/testing`, a fake Bluetooth stack for Jest. The other entries of this release add to it.
- 0048cd0: Advertising: `BleManager.startAdvertising(data, options)` advertises the phone as a peripheral on iOS and Android, one advertisement at a time, and resolves with an `Advertisement` to `stop()`. iOS advertises the local name and service UUIDs; Android also advertises manufacturer data, service data and the TX power level, with `android` options for the interval, transmit power, extended advertising and a timeout, but only the phone's own Bluetooth name. What a platform can't advertise is reported as a `NOT_SUPPORTED` warning. New config plugin options: `android.advertise` declares `BLUETOOTH_ADVERTISE`, and `ios.backgroundModes: ['peripheral']` adds the `bluetooth-peripheral` background mode. The testing entry gains `FakeBle.advertisement`.
- aa57edf: Android: `BleManager.registerBackgroundTask(taskName, { events: ['scanResults'], scan })` runs a background scan that delivers matching advertisements to an `expo-task-manager` task, waking the app even after Android stopped it; `unregisterBackgroundTask` stops it. On Android 10–11 it needs background location: the config plugin declares it with `android: { backgroundLocation: true }`. New types `BackgroundTaskOptions` and `BleBackgroundEvent`. On iOS, `registerBackgroundTask` rejects with `NOT_SUPPORTED` for now.
- 362f428: Service changes: when a connected peripheral's services change (iOS, and Android 12+), the library discovers them again, keeps the subscriptions that are still possible, and calls `peripheral.addServicesChangedListener` listeners. `peripheral.android.refreshGattCache()` clears Android's GATT cache and discovers again (hidden API, resolves `false` where unavailable). The Android connect option `android.resetAfterTimeouts` sets how many operations in a row may time out before the connection is reset (default 2, `false` to never reset), and a reset now reconnects when a `reconnect` policy is set.
- ac2d24c: Peripheral role: `BleManager.openGattServer(services)` publishes a local GATT server on iOS and Android. Static values are answered natively; `onReadRequest` and `onWriteRequest` handlers answer the rest within 25 s (else an ATT error and a warning). Long reads are served from one handler result per read sequence, long writes arrive as one value, thrown `BleError`s become ATT errors, and `addSubscriptionListener` reports CCCD subscriptions. The testing entry gains `connectCentral()`, a virtual central for testing server handlers. Advertising comes next.
- e2b635d: Android: `connect({ keepAliveInBackground: true })` keeps the app running in the background while the connection is open, with a foreground service of type `connectedDevice` that stops when the connection ends (reconnecting keeps it). Enable it with the config plugin option `android: { foregroundService: true }`; set its notification with `BleManager.android.setForegroundServiceNotification()`. A start Android refuses (the app was in the background) sends a `FOREGROUND_SERVICE_FAILED` warning. `getDiagnostics().android.foregroundService` tells whether it runs. On iOS the option still rejects with `NOT_SUPPORTED`.
- 9991e6d: Logging: `BleManager.setLogLevel(level)` and `BleManager.setLogHandler(handler)`. At `debug`, every GATT operation logs its id, kind, status and duration; `info` adds connection states and scans, `verbose` notifications. Logs go to Logcat (tag `BleKit`) and the iOS unified log (subsystem `expo.blekit`), and to the handler while one is set. A failed fire-and-forget `subscription.remove()` is logged as a warning.
- 09bdf35: `Peripheral.subscribeBatched(service, characteristic, onBatch, { intervalMs, maxItems })` collects notifications natively and delivers them at most once per `intervalMs`, each value with the time it arrived, so fast sensors don't flood the JS thread. When more than `maxItems` (default 4096) arrive in one interval, the oldest are dropped and counted in `dropped`, with a new `BUFFER_OVERFLOW` warning.
- f53b599: Reconnection policies: `connect({ reconnect: { maxAttempts, initialDelayMs, maxDelayMs, backoff } })` brings a lost connection back by itself, through the new `reconnecting` state, and restores subscriptions before `connected` (`restoreSubscriptionsOnReconnect`). On iOS 17 and later, `ios.enableAutoReconnect` lets the system reconnect first.
- 72e278b: GATT server notifications: `GattServer.notify(characteristic, value, { centrals })` sends a notification, or an indication to centrals that asked for one, to the subscribed centrals. It is flow-controlled on both platforms (Android waits for `onNotificationSent` per central and retries a busy stack, iOS waits for `peripheralManagerIsReady`), so awaiting each call paces a stream to the link. Values longer than a target's MTU − 3 reject with `INVALID_ATTRIBUTE_LENGTH`, a value waits at most 10 s, and centrals that disconnect drop out. The testing entry's `VirtualCentral` gains `notifications`.
- 99e825c: `Peripheral.writeStream(service, characteristic, data, options)` sends a payload of any length in chunks of one packet, natively and with flow control: `onProgress` reports about every 1 %, an `AbortSignal` stops it within the chunk in flight, `withResponse: true` acknowledges each chunk, and `chunkSize` makes chunks smaller. Operations issued during a stream wait until it ends.
- 271b3b3: Writes without response are flow-controlled: they resolve once the phone's Bluetooth stack took the packet and wait while it is full, so bursts are neither dropped nor failed. On Android a congested link no longer fails a write with `CONGESTED`, and a packet the stack refused while congested is sent again; on iOS a write that timed out while waiting is no longer sent later.

### Patch Changes

- b71e798: `getDiagnostics().sessions[].subscriptions` now counts each connection's active subscriptions; it was always 0.
- 9e82df4: Android: fixed a crash (`ConcurrentModificationException` in the scan controller) when many scan results arrived during a `reportIntervalMs` window. Scan results now reach the library's Bluetooth thread like every other callback.
